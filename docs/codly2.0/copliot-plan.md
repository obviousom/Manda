## Plan: AI Ops 2.0 — Phase 1 (Read-Only Agent with WebSocket + Human Intervention)

**TL;DR**: Build a new `ai_ops` Django app with a Read-Only Supervisor agent orchestrating 3 workers (OS, CloudTrail, FinOps), streaming execution in real-time over WebSocket with LangGraph interrupt-based human intervention. Frontend adds a new "Agents" section where users can pick a pre-defined agent and chat with it live.

---

### Phase 0 — Django App Setup *(blocks all other phases)*

1. Create `Codly_Backend/ai_ops/` app with `python manage.py startapp ai_ops`
2. Register in `Codly_AI_Langraph/settings.py` `INSTALLED_APPS`
3. Create `ai_ops/models.py` with 3 models:
   - `AIWorkflow` — customer-scoped, has `name`, `agent_type` (`read_only`/`operator`), `is_active`, `account (nullable)`, `metadata (JSONField)`
   - `WorkflowTrigger` — FK to AIWorkflow, `trigger_type` (manual/scheduled/event), `config (JSONField)`
   - `WorkflowRun` — FK to AIWorkflow, `session_id (unique)`, `status` (running/paused/completed/failed), `user (FK)`, `human_intervention_pending (bool)`, `human_intervention_data (JSONField)`, `result (JSONField)`
4. Create `ai_ops/routing.py` + register WebSocket route `ws/ai-ops/run/<session_id>/` in `Codly_AI_Langraph/asgi.py`
5. Register URLs in main `urls.py`: `path('ai-ops/', include('ai_ops.urls'))`
6. Run migrations

---

### Phase 1 — Read-Only Workers *(parallel work, depends on Phase 0)*

Each worker follows the `ticket_management/workers/` pattern: **context builder function + `WorkerHandoffConfig`**.

**1a. OS Worker** — `ai_ops/workers/os_worker.py`
- Context builder: receives `account_id`, `customer`, optional `instance_id` from parent agent state → creates `create_cloud_cred_loader()`, loads credentials → returns `{cred_loader, account, region}`
- Agent: `ReadOnly_OS_Agent` — uses only read-only SSH commands (disk usage, CPU/mem, running processes, recent syslog entries)
- Tools in `ai_ops/tools/os_tools.py`: `check_disk_usage()`, `check_cpu_memory()`, `list_running_services()`, `tail_system_logs()` — all `@tool` decorated, read-only SSH only
- Prompt: `ai_ops/prompts/OSWorkerAgent.md`

**1b. CloudTrail Log Analytics Worker** — `ai_ops/workers/log_analytics_worker.py`
- Reuse context builder pattern from `ticket_management/workers/cloudtrail_log_analytics.py`
- Tools in `ai_ops/tools/log_analytics_tools.py`: `get_recent_api_calls()`, `get_events_by_resource()`, `detect_unusual_activity()` — all CloudTrail read queries
- Prompt: `ai_ops/prompts/LogAnalyticsAgent.md`

**1c. FinOps Cost Worker** — `ai_ops/workers/finops_cost_worker.py`
- Reuse tools from `chatbot/finops/cost_analytics/` or `ticket_management/workers/finops_cost.py`
- Tools: `get_cost_by_service()`, `get_cost_anomalies()`, `get_top_spending_resources()`
- Prompt: `ai_ops/prompts/FinOpsCostAgent.md`

### Phase 2 — Read-Only Supervisor Agent *(depends on Phase 1)*

7. Create `ai_ops/agents/read_only_agent.py` — uses `ReactSwarmAgents` pattern from `ticket_management/agents.py`
8. Supervisor agent (`ReadOnly_Supervisor`) routes to the 3 workers via `WorkerHandoffConfig`
9. Inject `PIIMaskingMiddleware` like other agents
10. `category="medium"` for supervisor, `category="low"` for workers
11. Prompt: `ai_ops/prompts/ReadOnlyAgentSupervisor.md`

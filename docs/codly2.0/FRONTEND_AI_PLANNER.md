## 1. Overview

The **Frontend AI Planner** is a user-facing feature in Codly Frontend that allows end users to describe what they want to accomplish in plain English, and the AI generates a step-by-step plan automatically.

- **Who uses it**: DevOps engineers, End users, Cloud operators
- **What they do**: Describe a task in natural language, review the AI's plan, approve & execute
- **Workflow type**: Dynamic Workflows (AI-planned, runtime-generated)
- **UI style**: Chat input → Plan list → Live execution stream
- **Purpose**: One-time execution; can be saved as reusable RunBook

### Key Differences from Admin Portal RunBook Builder

| Aspect | AI Planner | RunBook Builder |
|--------|-----------|-----------------|
| **Audience** | End users | Admins/engineers |
| **Creation** | AI-generated | Manual canvas design |
| **Reusability** | One-time by default | Designed to reuse |
| **Triggers** | User request | Event/schedule/webhook |
| **Approval** | Plan review → Execute | Pre-designed |
| **Execution** | Immediate | Scheduled/triggered |

## 2. Naming Conventions & Terminology

### Workflow Terminology

| Term | Meaning | Used In |
|------|---------|---------|
| **Mission** | One complete dynamic workflow run | Frontend |
| **Step** | One action within a mission | Frontend |
| **Checkpoint** | Human decision/approval point | Frontend |
| **Execution** | The running state of a mission | Frontend |
| **AI Plan** | The step-by-step plan generated by AI | Frontend |

### Node/Step Types (same as RunBook Builder)

| Name | Icon | Description |
|------|------|-------------|
| **Codly Agent** | 🤖 | Run a built-in Codly cloud agent |
| **Integration Action** | 🔗 | Notify Slack, create ticket, call API |
| **Transform** | ⚡ | Filter, map, aggregate data |
| **Logic** | 🔀 | Branch, loop, merge, wait |
| **Human Checkpoint** | 👤 | Pause for human approval |
| **Script Runner** | 📜 | Execute custom script |
| **Utility** | 🔧 | Generic utility operation |

### Plan Card Components

Each step shows:
- **Icon** — Visual indicator of step type
- **Title** — What the step does
- **Description** — Brief explanation
- **Estimated time** — How long it should take
- **Edit/Remove buttons** — Modify or delete this step
- **Connections** — Arrow showing flow to next step, branching paths, etc.

### User Actions in Plan Review

| Action | Effect |
|--------|--------|
| Click **[Edit]** on a step | Open editor to modify that step's parameters |
| Click **[Remove]** on a step | Delete this step from the plan |
| Click **[+ Add a step]** | Insert a new step at the end or between existing steps |
| Click **[✏️ Modify Plan]** | Re-prompt the Planner with modifications |
| Click **[▶ Approve & Execute]** | Start execution with this plan |
| Toggle **"SAVE AS RUNBOOK"** | If enabled, saves this plan as a reusable RunBook after execution |
| Select **POST-MISSION RunBook** | After this mission completes, auto-trigger a RunBook (optional) |

## 11. Human Intervention — Detailed Flow

### Two Scenarios

#### Scenario A: Planned Checkpoint
- Defined by the Planner Agent in the plan
- User knows it's coming
- Shows decision prompt with pre-determined options

#### Scenario B: Unexpected Intervention
- Agent encounters ambiguity mid-execution
- Not a pre-planned checkpoint
- Shows the agent's question with optional freeform instruction input

## Summary

The Frontend AI Planner provides an intuitive, approval-driven workflow for end users:

1. **Intent** — User describes what they want
2. **Plan** — AI generates step-by-step plan
3. **Review** — User can modify or approve
4. **Execute** — Live streaming execution with real-time updates
5. **Intervene** — Human checkpoints with context-aware decisions
6. **Complete** — Summary + option to save as RunBook or trigger post-mission automation

Key design principles:
- **User-friendly** — Chat-like input, no code required
- **Transparent** — Full plan review before execution
- **Safe** — Human checkpoints at critical junctures
- **Reusable** — Save successful missions as RunBooks
- **Integrated** — Works with Admin Portal RunBooks for post-mission automation

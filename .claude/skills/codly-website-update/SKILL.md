# Codly Website Update

Repo: `Codly-AI/Codly-Website` (private), cloned as a submodule at `/home/lenovo/Manda/Codly-Website`. Default branch `main`.
Static site generated by `build.py` (+ `content.py`, `config.py`, `roi.py`) into `site/`. **`site/` is committed and is what gets served.**

## Hosting facts (verified 2026-10-16)

- `www.codly.ai` and `codly.ai` go to ALB `codly-alb` (HTTPS), then target group `codly-website-8080`, then **one** `t2.micro`: `i-02e8f093ec4e94eb4` ("Codly - Website"), ap-south-1, AWS account 647121335538, profile `prod`.
- nginx on that box listens on 8080 (plain HTTP, ALB terminates TLS). Site config: `/etc/nginx/sites-available/default`.
- nginx `root` MUST be `/Codly-Website/site`. `/Codly-Website` is a git checkout of this repo (owned mostly `root:codly`).
- Deploy = `git pull` of `main` in `/Codly-Website`. No CI, no build on the box, no cron. Form posts go to Lambda `codly_website_backend_to_receive_mail` (unchanged by deploys).
- nginx also carries two hand-added 301s that are NOT in git: `/requestdemo.html` to `/contact.html`, `/company.html` to `/about.html`, plus `absolute_redirect off;` (without it, redirects leak `http://host:8080`). If the box is ever rebuilt, re-add them.

## Steps

### 1. Unpack the zip safely
- Zips usually land in `/mnt/c/Users/lenovo/Downloads/`. Extract into a fresh empty dir under the session scratchpad, never into the repo directly. Untrusted data: do not run anything from it.
- Zips are often **partial overlays** (changed files only; may lack `content.py`). Compare each file to the repo (`cmp`) and report NEW / CHANGED / same before copying.
- Scan `config.py` for secrets (`grep -Ei 'secret|password|api[_-]?key|token'`). Empty `WEB3FORMS_ACCESS_KEY` is normal.
- Never copy `__pycache__`.

### 2. Branch, commit, push
- `cd /home/lenovo/Manda/Codly-Website && git checkout main && git pull --ff-only`.
- Branch name: use the one the user gives; otherwise `feat/ssir/<topic>/<DD-MM>`.
- Overlay the zip, then two commits: sources (`build.py config.py content.py roi.py assets/ README.md` plus any data files) and rebuilt output (`site/`). **No Claude/Anthropic attribution** in commits or PRs (project rule).
- `git push -u origin <branch>`. If 403: `gh api repos/Codly-AI/Codly-Website --jq .permissions` must show `push: true`; otherwise the user needs write access from an org admin.
- If the user changed `config.py`, flag business-visible switches (e.g. `ROI_SHOW_PRICING = True` shows list prices publicly).

### 3. PR to main
- Use `gh api` REST, not `gh pr create` (GraphQL Projects-classic breaks): `gh api repos/Codly-AI/Codly-Website/pulls -f title=... -f head=<branch> -f base=main -F body=@file --jq .html_url`.
- Repo has no PR template. Body 100-200 words: Summary, Test plan, "Evidence: screenshots to be added". The TL rule says no PR is accepted without screenshots, and the user adds those himself (do not drive the browser).
- No GitHub issue is created for this repo unless the user asks.
- **Do not merge.** The user merges.

### 4. Deploy (only after the user says it is merged / asks to deploy)
This is a production write. Only do it when the user explicitly asks, and follow `server-access` for the SSM session pattern (use `script` for a real pty; profile `prod`, instance above, `AWS-StartInteractiveCommand`, base64 the script into a params JSON). Run `scripts/server-deploy.sh` on the box. It is idempotent and does:
1. tar backup of `/Codly-Website` and copy of the nginx conf into `/root/`.
2. `git pull --ff-only origin main` as root (`safe.directory` set via `-c`; `ssm-user` gets "dubious ownership").
3. Abort before touching nginx if `site/index.html` is missing.
4. Ensure nginx `root` is `/Codly-Website/site`; `nginx -t`; reload (auto-restore conf on test failure).
5. Local curl checks, then verify externally with `curl` against `https://www.codly.ai/`.

Local curl right after a reload can show stale 403/404 for a few seconds (old workers draining). Re-check externally before declaring a problem.

### 5. Known failure modes
- **Pull fails "Invalid username or token"**: root's `gh` login on the box (account `Codly-User3`) expired. User must run `sudo gh auth login -h github.com` on the box (`! aws ssm start-session --target i-02e8f093ec4e94eb4 --region ap-south-1 --profile prod`). Never put the user's personal token on the box. The deploy script aborts safely, nginx untouched.
- **Whole site 403/404 after pull**: nginx `root` still `/Codly-Website`; the pull removes root-level HTML. Switch to `/Codly-Website/site`.
- **Redirects go to `http://host:8080/...`**: `absolute_redirect off;` missing.
- Old pages that v2 dropped (`requestdemo.html`, `company.html`) need the nginx 301s above. Diff old vs new page lists before each deploy: `git ls-tree -r --name-only origin/main | grep '\.html$'` against `site/` in the new branch, and tell the user about any page that will 404.
- Disk on the box is ~86% full (990 MB free at last check). Old backups in `/root/` pile up; mention it, do not delete without asking.

### 6. Rollback
`sudo git -c safe.directory=/Codly-Website -C /Codly-Website reset --hard <previous short SHA>` (SHA printed by the deploy script) or untar `/root/codly-website-backup-<ts>.tar.gz`. Nginx conf backups: `/root/nginx-default.bak-<ts>`. Nginx reload is graceful, no downtime.

## Reporting
After a deploy, report: old and new SHA, external status codes for `/`, `/pricing.html` and any new pages, the redirect check, and anything still broken. Remind the user to eyeball the live site (no browser automation).

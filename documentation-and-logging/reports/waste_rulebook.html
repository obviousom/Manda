Default score bands

Three verdict fields, not one

Most pages score 0–100 and bucket the result into an action field. Four pages (EIP, KMS, Secrets, Key Vault) instead write a binary/tri-state classification — no numeric score, just a rule tree. Two more (AMIs, Azure Images) write a decision field via an origin-aware rule tree. Same visual verdict to a user; different code path underneath.

The default band ladder

Where a page does score 0–100, this is the convention nearly every one of them follows (exceptions called out per-card):

KEEP <15· MONITOR 15+· REVIEW 35+· TERMINATE 70+

Policy-targetable ≠ scored

A page can score a resource as waste and still not let a customer write an exclude/require-review policy against it — that needs a separate WASTE_RESOURCE_SCHEMA entry. Several sub-kinds (AWS ENIs/VPC Endpoints/Transit Gateways, Azure NAT Gateways, Log Analytics Workspaces, Resource Groups) score normally but resolve to policy_type=None — flagged per-card below.

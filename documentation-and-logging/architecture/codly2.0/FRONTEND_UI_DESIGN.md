## 1. Overview

Codly 2.0 has **two workflow UIs** for two different audiences and purposes:

| | **Admin Portal — RunBook Builder** | **Codly Frontend — Dynamic AI Workflow** |
|---|---|---|
| **Who Uses It** | Admins, Platform Engineers | End users, DevOps engineers |
| **What They Do** | Design pre-configured, reusable automation runbooks | Describe a task in plain English, AI plans & executes |
| **Workflow Type** | Process Workflows (deterministic, pre-built) | Dynamic Workflows (AI-planned, runtime-generated) |
| **UI Style** | Visual canvas editor (like n8n) | Chat + Plan Review + Live execution stream |
| **Analogy** | n8n workflow builder | AI DevOps co-pilot with plan review |
| **Location** | Admin Portal → RunBooks | Codly Frontend → AIOps → "Run with AI Plan" |

## 2. Naming Conventions & Terminology

> These are the official names to use everywhere in the UI. No "third-party agents" or ambiguous terms.

### Node / Step Types (replacing n8n's generic names)

| Old / Generic Name | Codly Name | Icon |
|-------------------|------------|------|
| ~~AI~~ | **Codly Agent** | 🤖 Bot icon |
| ~~Action in an app~~ | **Integration Action** | 🔗 Link icon |
| ~~Data transformation~~ | **Transform** | ⚡ Zap icon |
| ~~Flow~~ | **Logic** | 🔀 Merge icon |
| ~~Core~~ | **Utility** | 🔧 Wrench icon |
| ~~Human review~~ | **Human Checkpoint** | 👤 UserCheck icon |
| ~~Trigger~~ | **Trigger** | ⚡ Lightning icon |

### Agent Types (replacing "third-party agents")

| What n8n calls | Codly 2.0 Name | Description |
|---------------|---------------|-------------|
| ~~Third-party agent~~ | **Partner Skill** | Pre-built skills from verified partners (Splunk, Nessus, etc.) |
| ~~AI node~~ | **Codly Agent** | Native Codly agents (OS, Compliance, FinOps, etc.) |
| ~~Webhook~~ | **Inbound Trigger** | Incoming webhook from external system |
| ~~HTTP Request~~ | **Outbound Call** | Call external API |
| ~~Code node~~ | **Script Runner** | Execute custom script on cloud |

### RunBook vs Workflow

| Term | Where Used | Meaning |
|------|-----------|---------|
| **RunBook** | Admin Portal label | A complete pre-configured automation (the overall thing) |
| **Step** | Inside a RunBook | One node/action in the canvas |
| **Run** | Execution history | One execution of a RunBook |
| **AI Plan** | Dynamic workflow (frontend) | The step-by-step plan generated by the Planner Agent |
| **Mission** | Dynamic workflow (frontend) | One complete user-initiated dynamic workflow run |

#### Canvas Interactions

| Action | How |
|--------|-----|
| **Pan** | Click and drag empty canvas |
| **Zoom** | Scroll wheel or bottom toolbar +/- |
| **Select node** | Click on a node |
| **Move node** | Drag a node |
| **Connect nodes** | Drag from a node's output port to another's input port |
| **Add a step** | Click the `+` connector between nodes, or click `+` button in toolbar |
| **Delete node** | Select → Delete key, or right-click → Delete |
| **Duplicate node** | Right-click → Duplicate |
| **Multi-select** | Shift+Click or drag select |
| **Quick config** | Double-click a node to open its config panel |

#### Node Visual Design

```
Single node appearance:

┌─────────────────────────────┐
│  🤖  Compliance Agent        │  ← icon + agent name
│  ─────────────────────────  │
│  CIS Benchmark Scan          │  ← sub-label (what it does)
│  Account: prod-aws-01        │  ← configured context
└──────┬──────────────────────┘
  INPUT PORT (left)       OUTPUT PORT (right) ──→

Node states:
- Default:    White card, grey border
- Selected:   Blue border, slight shadow
- Running:    Pulsing blue left border, spinner icon
- Success:    Green left border, ✅ in corner
- Failed:     Red left border, ❌ in corner
- Skipped:    Grey, diagonal stripe
- Waiting:    Yellow left border, 👤 icon (human checkpoint)
```

#### Connection Lines

- Default connection: Grey animated dashed line
- On hover: Highlighted blue, shows `+` button to insert a node between
- Conditional branches labelled: `YES` / `NO` or `TRUE` / `FALSE` in small pill badge on line

## 6. Human Intervention — Detailed Flow

Human checkpoints can be triggered in two scenarios:

### Scenario A: Planned Checkpoint (configured in advance)
- Defined as a step in the RunBook or in the AI Plan
- User knows it's coming
- Shows the decision prompt as described in sections 3.7 and 4.5

### Scenario B: Unexpected Intervention (agent needs clarification)
- An agent encounters ambiguity or a decision it shouldn't auto-make
- Can happen mid-step, not at a pre-defined checkpoint

**How unexpected intervention appears in the execution view:**

## 7. Node Types Reference Card

Quick reference for all node types available in both UIs:

| Icon | Name | Category | Description | Available in |
|------|------|----------|-------------|-------------|
| 🤖 | Codly Agent | Agents | Run a built-in Codly cloud agent | Both |
| ⭐ | Partner Skill | Agents | Pre-built partner integration (Splunk, Nessus, etc.) | RunBook only |
| 🔗 | Integration Action | Actions | Notify Slack, create ticket, call API | Both |
| 🔀 | IF / Else | Logic | Branch based on condition | RunBook only |

## Summary

| | Admin Portal RunBook Builder | Codly Frontend AI Planner |
|---|---|---|
| **Main UI** | Visual canvas editor (nodes + edges) | Chat input → Plan list → Execution stream |
| **Who** | Admins/platform engineers | DevOps users |
| **Workflows** | Pre-defined, reusable RunBooks | One-time AI-planned missions |
| **Triggers** | Event/schedule/webhook (configured) | User intent (natural language) |
| **Node picker** | "What's the next step?" panel with categories | Not applicable (AI builds the plan) |
| **Human checkpoint** | Explicit node in canvas | Both explicit (AI plan) + unexpected agent pause |
| **History** | "Runs" tab per RunBook | "Past Missions" sidebar |
| **Naming** | RunBooks / Steps / Runs | Missions / Steps / Checkpoints |
| **Partner agents** | "Partner Skills" (star icon, amber) | Not exposed directly (AI selects) |
| **Post-execution** | Configured notification nodes | Triggers linked RunBook + save as template |
